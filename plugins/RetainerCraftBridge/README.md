# 雇员收取后制作 · RetainerCraftBridge

独立 Dalamud API 15 插件。**指定制作角色收完雇员后转入 Artisan 制作；开头角色的雇员再次到期后安全停工，返回开头并重新开启 AutoRetainer。** 不统计全账号是否“收完一轮”，不替换或修改原插件程序。

## 使用

需要已配置好、可单独正常工作的 AutoRetainer、Artisan 和 Lifestream。安装本仓库的插件发布包，用 `/retainercraft` 打开设置。

1. 停止原 AR 多角色模式，范围设为 **Retainers（仅雇员）**。选择器默认隐藏：输入 `/ays settings` → **高级设置 → 专家设置 → 显示多角色模式类型选择器**，再回 `/ays` 主窗口，在“多角色”旁选择 `Retainers`。`Submersibles` 是潜艇，`Everything` 同时包含雇员和潜艇；为在雇员收取结束时交接，本循环要求 `Retainers`。关闭其旧 Artisan 整合、RetainerSense / OldRetainerSense、全自动军票交付、夜间模式、一次性同步等待。结束当前自动任务。
2. 刷新角色列表，选择**开头角色**和**制作角色**。两者可以相同，均须在 AR 启用雇员轮换，且有已勾选、执行中的探险。其余角色及顺序使用 AR 原有设置。
3. 选择具体职业对应的配方、**每个制作时段的次数上限**及**此配方的制作方式**。制作方式按配方编号保存，可让一种材料使用标准制作、另一种使用简易制作。次数是制作尝试次数，界面显示预计产量；开头到期时可能提前结束。只支持标准制作配方，不支持星海探索制作。
4. 点击“只检查条件”，勾选启用，再点击“开始循环”。加载、重载插件不会自动开始。
5. 可启用**制作前从雇员取出缺少的材料**，并调整取料、制作各步骤延迟。插件通过 Lifestream 切到开头，开启 AR 原生轮换。指定制作角色收取成功且退出雇员交互后，停住后续换角，按需取料，再制作。
6. 开头再到期时，停止本次取料或制作，等自己的界面和在途操作退出，再回到开头继续轮换。次数正常用完后继续等待开头；缺料、制作失败或结果不明时不盲目重试。若进入制作边界时开头已经到期，则直接返回收雇员阶段。

## 简易制作与材料

| 制作方式 | 行为与条件 |
| --- | --- |
| 标准制作 | 桥接器逐次启动普通工艺，Artisan 按已有求解器或宏执行技能。须先在 Artisan 开启自动模式，并在桥接界面确认；不保证 HQ。停止后不再开始下一件，当前工艺需完成或手动结束。 |
| 简易制作 | 桥接器明确启动简易制作，每批最多 99 次，再继续剩余次数。配方必须支持，且制作角色已完成过；不满足时停止，不回退到普通制作。停止会撤销后续批次，并请求结束本次简易制作。 |
| 跟随 Artisan 设置（兼容方式） | 保留 `Artisan.CraftItem(配方, 次数)` 路径。是否简易由 Artisan 的 `Use Quick Synthesis where possible` 和角色配方解锁决定。该接口没有模式参数，也不能直接移除 Artisan 私有队列。 |

标准与简易两种明确方式使用桥接器自己的任务队列，不改变 Artisan 全局模式。尚未保存过制作方式的配方默认选择标准制作；使用前确认 Artisan 自动模式，或改选简易制作。制作角色需要已处于正确职业并穿好装备；这两种方式不会代执行 Artisan 连续制作的换装、食药、修理和精炼预处理。标准制作的材料按 NQ 优先、HQ 补足分配；每次开工前重新核对配方、职业、材料与本次窗口。具体原生参数和限制见[制作证据](https://github.com/Houraiji9/FFXIV-StandalonePlugins/blob/main/plugins/RetainerCraftBridge/CraftNative.md)。

启用自动取料后，先按**本时段全部制作次数**计算材料与水晶需求，扣除背包已有 NQ/HQ，再逐个检查当前制作角色可用雇员的真实库存。仅取缺少的数量，按源格减少和背包增加核实每笔取出；不依赖 Allagan Tools 缓存，不取其他角色的雇员。需要在可交互的雇员铃旁并有足够容量；不会自动寻找或传送到铃。

材料不足、持有上限不够、出现无关窗口或取出结果不明时停止，已经成功取出的材料留在背包，不自动放回。不会悄悄降低制作次数，也不会重复提交不明的取出请求。取料期间开头角色到期，会撤销后续取料，等已提交动作及自己打开的界面收尾后交回 AR。

取料六项、明确制作方式七项动作延迟分别可调，动作至少间隔 100 毫秒、同一帧最多一个原生操作；主动延迟不占用对应的响应超时。停止和关闭窗口同样遵守间隔。

## 判定与兼容限制

开头就绪只检查该角色的已选、执行中探险，沿用 AR 当前 `MultiWaitForAll`（任一/全部）及 `AdvanceTimer` 提前窗口。“全部”只指开头角色的雇员。没有任务、角色禁用/排除或数据不可读时停止交接，不把空集合当作到期。提前恢复轮换不保证当时立刻可收，实际收取仍由 AR 调度。

AR 私有的一次性 `Synchronize` 状态没有公开 getter；本插件无法读取或复刻。运行前请取消该同步等待。

制作角色到访时按 AR 当前角色的 300 秒 `Done` 视窗观察待收目标，每个目标都要求**自己的后处理握手 + 公开探险状态更新**。许可/空间不足、队列空闲或单纯 `Done` 不算成功；没有待收目标的到访不拦截。

在自己的角色后处理回调中同步执行 `DisableAllFunctions → AbortAllTasks → FinishCharacterPostprocessRequest`，撤销 AR 已经排队的下次换角。没有角色后处理通知时，只有收取证据齐全、角色正确、UI 和队列空闲才使用替代边界。该逻辑不检查其余角色是否收齐。

本流程独占 AR / Artisan / Lifestream，不支持其他自动流程、手动换角或改配方同时运行。AR 的任务清空会影响后面的其他插件后处理。结束保持多角色模式关闭；公开运行开关可能随 AR 的正常配置保存，不保证其配置文件字节不变。本插件不直接写其他插件配置，不使用私有反射。

若已加载 YesAlready，运行与清理期间通过其公开共享暂停接口持有本插件独立的请求，防止自动确认提前处理当前窗口。结束或卸载只移除自己的请求，不解除其他插件的暂停；无需为此额外安装 YesAlready。

## 停止与失败

点击窗口顶部的“停止循环”或输入 `/retainercraft cancel`。停止按钮在清理期间仍保留；尚未执行的开始请求也能取消。停止意图在下一次框架处理原生队列前应用，撤销本插件尚未发送的动作。

- 停止拥有的 AR/Lifestream 队列，只释放自己的锁。已提交给游戏的登出、登录、传送不能撤回。
- 自有制作队列立即停止后续开工；标准工艺继续完成当前件，简易制作发送已核实属于本次工艺的取消请求。正常切回收取时，要等各队列和 UI 稳定空闲后才恢复 AR；主动停止循环时不恢复 AR。
- 兼容方式在公开接口确认 Endurance 已接收后，即使尚未见到第一件开工，也能关闭。已开始的普通工艺保留到安全间隙，避免清掉 Artisan 的自动技能覆盖；已开始的简易制作立即关闭后续重复，但当前批次仍需退出。
- 不使用 `SetStopRequest(true → false)`，因为它会恢复旧制作。外部暂停、其他列表、错角色、配方改变、迟到制作或未释放界面都会保持 AR 关闭，不强行恢复或重复提交。
- 换角等待 3 分钟、雇员界面退出 2 分钟、安全停工 10 分钟，原生轮换不到目标边界最多 2 小时；超时会显示失败。
- 兼容方式的 `CraftItem` 是异步入队。90 秒没观察到实际开始会失败，不重试、不恢复 AR。公开 API 不能删除私有预处理，且 `IsBusy` 不包含所有预处理任务；尚未确认接收的请求不能凭空闲或超时当作已撤销。此时需手动清理 Artisan，必要时关闭/重载 Artisan 后重载桥接器。明确标准/简易方式不使用这条队列。
- **先停止循环、等空闲再卸载。** 强制卸载只能同步尽力停止拥有的动作；当前工艺可能需手动完成，尚未启动的 Artisan 请求可能仍在其队列中，日志会明确告知。
- “已开始”或“自然结束”都不证明全部物品制作成功；本插件不提供成品数量验收。

## 兼容与开发验证

静态核对版本：Dalamud API 15 / .NET 10；AutoRetainer 4.6.0.8（Ookura-Risona，`d57cb55c`）；Artisan 4.0.5.21（`e438055`）；Lifestream 2.6.0.5（`52c54fad`）。其他版本需要相同 IPC 及语义，缺接口会拒绝启动。

只分发本插件 DLL 和 manifest，使用最小公共 DTO，无原插件二进制依赖，不使用私有反射。按钮操作在 framework 线程执行，Ready 截停保持同步。0.1.4 的取料和明确制作模式使用已核实的公开原生绑定，限制客户端版本为 `2026.10.06.0000.0000`；版本不符时不发送原生动作。

仓库根目录可执行：

```powershell
dotnet build plugins/RetainerCraftBridge/RetainerCraftBridge.csproj -c Release
dotnet run --project tests/RetainerCraftBridge.Tests/RetainerCraftBridge.Tests.csproj -c Release
```

测试覆盖开头到期规则、两次连续循环、原生其他角色轮换、收取证据、握手顺序、异步启动竞态、取料交接、取消、迟到任务、角色/配方所有权及卸载边界。独立材料与制作规则测试覆盖数量、容量、增量、次数和延迟。测试使用隔离 fake host 与纯规则，不连接游戏。

**当前只有编译、隔离测试及静态审查记录，没有真实游戏安装、运行或用户验收记录。发布不改变这一验证边界。**
