# 多角色雇员直售（RetainerVendorSweep）

独立 Dalamud API 15 插件，版本 **0.1.6.0 预发布候选**。指定客户端的整堆直售入口已完成静态核实和离线检查；实际发行状态以 GitHub Release、自定义安装索引和任务交付记录为准。静态结论不代表已完成真实出售或多角色流程验收。

## 功能范围

- **只出售当前角色普通背包中的物品。** 不从雇员仓库取物，不出售雇员仓库、兵装库或其他仓储中的物品。
- **白名单表示保留不售。** 添加到白名单的物品会跳过；它不是待出售列表。
- 出售规则可按物品或品类选择，再选择允许的 NQ／HQ。保留名单优先于出售规则；没有匹配出售规则的物品也不会出售。
- 每次提交的是匹配源格的**整堆物品**，不提供部分数量输入。普通出售路径直接调用雇员直售入口，不先打开右键菜单，也不使用数量输入窗口。
- 从 AutoRetainer 的已知角色资料中选择本次处理角色，使用 Lifestream 换角。该资料不等于全账号角色自动发现，需要用户先让相关角色被 AR 识别。
- 各角色需要已经位于可以交互的雇员铃附近。插件不提供导航、寻找雇员铃或传送到铃。
- 用户手动启动后，按选择的角色依次处理，每个角色一遍，全部结束即停止，不循环运行；加载或重载不自动开始。
- 每个步骤的延迟可配置。出售属于有副作用的游戏操作，停止会先撤销尚未发送的步骤；已提交请求必须按实际响应处理，不能把超时当作已经撤回。

## 命令与使用流程

| 命令 | 用途 |
| --- | --- |
| `/retainersell` | 打开配置与运行界面 |
| `/retainersell stop` | 请求停止本次遍历与后续出售 |

使用顺序是：先完成下列插件共存设置，刷新并选择 AR 已知角色，设置出售规则、保留白名单和延迟，查看当前角色的背包预览，核对本轮清单后手动开始。其他角色的真实背包需在登录后读取；预览不是整个账号的库存。每个角色通过附近的雇员铃进入直售流程，出售只针对符合条件的角色背包格；成功结果须由实际状态核对，失败或不明结果不得盲目重复提交。

首版运行前：

1. **暂时禁用 RetainerCraftBridge／雇员收取后制作插件。** 它没有公开运行状态 IPC，仅保持窗口关闭或声称空闲，不能供新插件确认排他状态。
2. 保持 AutoRetainer 与 Lifestream 已加载，但停止其当前任务，关闭 AR 多角色模式、RetainerSense／OldRetainerSense、夜间模式、自动军票交付，以及启动游戏或加载插件时自动开启多角色的选项（`MultiAutoStart`、`MultiOnPluginLoad`）。
3. 在 `/ays settings → 高级设置 → 专家设置 → 行为设置` 中，将“无可用派遣任务时访问雇员铃的操作”和“有可用派遣任务时访问雇员铃的操作”均设置为 **Disable_AutoRetainer（禁用 AutoRetainer）**。默认“启用”会在本插件打开铃时让 AR 抢先调度；“无操作”也不能关闭之前已启用的单角色调度。
4. Artisan 可以保持加载，但必须停止制作、连续制作和列表，保持空闲。停止其他换角、交易、背包和雇员自动流程，不同时手动操控这些界面。

每个角色开始直售前，插件通过公开 `AutoRetainer.PluginState.DisableAllFunctions` 清除旧的运行开关；不替用户改写上述配置项，也不在完成、失败或停止后自动恢复 AR 运行。已经提交的外部请求仍需等待结果，不能把关闭开关视为撤销请求。

## 整堆直售与步骤延迟

针对目标客户端的静态核查已确认：公开 `AgentRetainer.HandleCallback(源格, 背包容器, 0, 5)` 的 command 5 是直接提交源格整堆直售的入口，后续走商店／雇员出售流程。它不经过 `ContextMenu`，也不要求 `InputNumeric`；不能照搬取料的数量窗流程。

界面中的“提交整堆直售”延迟控制这一实际提交动作，配置字段为 `ContextMs`。旧类型中的 `QuantityMs` 仅保留兼容，不显示为可调数量步骤，也不产生数量窗口操作。其余界面列出的步骤分别等待自身延迟；出售确认与最终结果仍需按对应窗口、物品和状态校验。陌生数量窗口不能被当作本次出售窗口自动填写。

源格、售价、金币变化、可能出现的出售确认和停止时在途请求均须由实现核对；静态核实直接入口不等于所有成功、取消和异常分支已通过游戏验收。

## 环境与依赖

开发目标为 Windows x64、.NET 10、国服 Soil／Dalamud API 15，固定 SDK 为 `26-11-03-01`。manifest 的适配目标限定 `2026.10.06.0000.0000`；这是一项版本限制，不是已经通过游戏验证的声明。

运行设计依赖 AutoRetainer 的公开角色资料与 Lifestream 的公开换角接口，不替换原插件 DLL，不需要 Artisan 或 DailyRoutines 承担出售。接口研究基准为 AutoRetainer 4.6.0.8、Lifestream 2.6.0.5；不能假定其他版本的接口和时序相同。

源码与另外两个插件同处 [FFXIV-StandalonePlugins](https://github.com/Houraiji9/FFXIV-StandalonePlugins)，分别安装、分别配置。现有自定义仓库地址仍为：

```text

```

发布完成后，在此索引中搜索“多角色雇员直售”或 RetainerVendorSweep。若索引尚未提供此插件，请以对应 Release 的实际发布记录为准。BatchTrade 保持 0.1.5.0，RetainerCraftBridge 保持 0.1.4.0，其现有索引条目不随本次开发修改。

本轮完成、停止或失败的记录保存于本插件配置目录的 `runs` 子目录，包含各角色结果和已核实的出售数量、金币。记录只保存在本机，不上传 GitHub，也不用于加载后的自动恢复；失败时尚有在途请求会在记录中明确标为仍阻塞。

## 构建与打包

在仓库根目录执行，固定 SDK 的获取方式见根说明：

```powershell
dotnet build plugins/RetainerVendorSweep/RetainerVendorSweep.csproj -c Release
dotnet run --project tests/RetainerVendorSweep.Tests/RetainerVendorSweep.Tests.csproj -c Release
./scripts/Package.ps1 -Tag v0.1.6 -Plugins @('RetainerVendorSweep')
```

`Build.ps1` 构建三个插件并运行各插件测试及既有材料、制作规则测试。选择性打包只生成 `RetainerVendorSweep.zip`、合并后的 `pluginmaster.json`、`SHA256SUMS.txt`；输出索引保留两个未选中插件的完整已有条目。它不写根索引、不提交或发布，非空输出目录拒绝覆盖。

2026-11-03 只读查询 GitHub 未发现 `v0.1.6` 或 `v0.1.6.0` 标签，因此暂用版本 0.1.6.0；这不预留标签，发布前需要重查。
