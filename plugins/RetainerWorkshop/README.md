# 雇员工坊（RetainerWorkshop）

独立 Dalamud API 15 插件，版本 **0.1.8.0 预发布**。将雇员收取、可选制作、角色背包直售和周期累计交给同一个调度器。加载、重载及导入配置都不会自动运行；制作阶段与日／周自动直售默认关闭。

当前版本尚未完成真实游戏内的收取、取料、制作、出售及多角色整合流程验收。构建、离线测试、代码审查和实际发布分别记录，不能代替实机验收。发行状态以对应 GitHub Release 和安装索引为准。

## 功能与轮次口径

- 设置**开头角色**和**收尾角色**，由 AutoRetainer 原生调度中间角色。只有收尾角色本次目标雇员取得后处理及探险状态更新证据，且 AR 队列、雇员交互已释放，才累计完成一轮。
- 这里的一轮是“从开头角色启动，到收尾角色收取确认”的业务段，**不证明全账号所有角色均已访问或收齐**。AR 的勾选角色、雇员及顺序仍由 AR 配置决定；资源不足、失败、提前停止和单纯收到角色后处理通知均不能算成功。
- **制作角色单独设置**，可以与首尾角色不同。收取结束后返回该角色，核对实际 CID 和空闲状态，再开始制作。开头角色再次进入到期窗口时停止后续制作，安全收尾后开始下一段收取。
- 可选择每日或每周累计完成 **N 轮后自动直售一次**。周期内只登记一个自动出售任务，不是每 N 轮反复出售；时间区间按配置的时区、重置时间及每周起始日计算。
- 可设置本次手动运行完成 **M 轮后停止**；`0` 表示不设置这一上限。达到 M 后先完成本轮已经触发、排队或暂停的出售任务，然后整体待机，不再开始收取或制作。
- 也可以手动执行一遍直售，不启动收取或制作。直售范围来自 AR 已知角色缓存，可调整顺序和排除角色；这不是自动发现全账号角色。

## 日／周累计示例

| 设置 | 行为 |
| --- | --- |
| 每日 N = 5 | 当日第一次累计到 5 个已确认业务轮次时，登记一次自动出售；当日继续到 10 轮也不会再次自动出售。 |
| 每周 N = 20 | 同一配置周内累计到 20 轮后出售一次；跨天继续累计，进入下一周后重新累计。 |
| 每日 N = 5，本次 M = 8 | 当日累计达到 5 时触发出售；本次运行确认完成 8 轮时，先收尾已经触发的出售任务，再整体待机。 |
| 本次 M = 3，当日此前为 0、N = 5 | 完成 3 轮后待机，本次没有达到自动出售阈值。同周期再次手动开始时，已持久化的周期累计继续保留。 |

周期累计只记录**启用了日／周规则的手动运行期间**已确认的完成事件，不补算此前关闭规则时的轮数。每次完成事件按其确认时刻归属周期。M 则始终从本次手动开始计数，不沿用上次运行的 M 进度。

更改周期或阈值不会清除已发任务，也不能重新获得当前周期的出售机会；实际生效条件见界面周期状态。重载发现未核实任务、记录损坏或写入失败时停止自动流程，要求人工核对，不靠删除记录或自动回退备份重发出售。人工确认仅解除中断阻塞，不会续跑旧请求。

## 出售与收取的交接

出售期间开头角色到期时，先完成**当前角色**的出售会话及界面收尾，再记录下一角色位置、暂停出售并返回收取。下一次收尾后继续**同一出售任务**，不会重新处理已经完成的角色。

每次恢复出售至少处理一个角色，再响应到期暂停，避免收取持续到期造成出售一直没有进展。达到 M 的停机决定生效后，不再为到期事件开启收取；将已触发出售做完后待机。用户手动停止优先撤销所有后续阶段，尚未处理的角色不会继续。

直售仅处理角色普通背包 `Inventory1..4` 中匹配规则的**整堆物品**，按 NPC 售价出售，金币进入角色钱包。不挂市场板，不出售雇员仓库、兵装库或其他仓储，也不提供部分数量出售。

出售可按指定物品或 `ItemUICategory` 品类匹配，NQ／HQ 分别选择。**白名单表示保留不售**；全局与任何品类下的保留名单都优先于全部出售规则。提交前重新检查源格及保护规则，结果必须核对源格数量和角色金币增量；结果不明不重试。

各出售角色须已位于附近可交互的雇员铃旁；插件不导航或传送寻找铃。背包预览只反映当前角色，其他角色登录后读取真实背包。

## 从当前背包建立出售名单

在 `/workshop` 的“出售与保留名单”页，点击“读取／刷新当前角色背包”，然后勾选物品前的“出售”。勾选立即保存到出售名单，不需要再从全部道具库搜索或另按添加按钮，也不会因此开始出售。

- 背包列表独立于出售规则：尚未设置名单也会显示普通背包的全部物品。同一道具的多堆合并为一行，分别显示 NQ、HQ 数量和占用格数。品质开关决定哪些品质可出售；名单按物品 ID 保存，应用到本插件选中的出售角色。
- 取消“出售”会移除该物品的明确选择。如果所属品类仍设为整类出售，会自动把该物品加入保留名单，确保取消后不会被整类规则再次选中。
- 已在白名单中的物品继续保留。只有明确取消该行的“保留不售”，才能解除该物品在全局及品类保留名单中的保护；单击出售不会暗中解除保护。
- 不可直售、无法识别的物品仍显示并注明原因，不能从背包勾选为出售。背包总数与规则匹配数分别显示，读取失败、真正空背包、规则零匹配和搜索无结果有不同提示。
- 列表是带读取时间的库存快照；修改名单不会清空列表，物品变化后请主动刷新。切换角色、退出登录或开始运行会清除快照，执行出售时仍重新读取和核验真实背包。

“从全部道具库添加／按品类出售”保留作为额外入口。“核对全部出售品类与保留名单”也保留，当前角色未持有的物品选择不会被读取背包清除。

## 制作与取料

每个配方可单独保存制作方式，次数是**每个制作时段的尝试上限**，预计产量不代表成功产量，也不保证 HQ。

| 方式 | 要求与停止行为 |
| --- | --- |
| 标准制作 | 当前角色须处于配方对应职业、装备和材料条件可用，并在 Artisan 开启自动模式。使用本插件可取消的启动队列，由 Artisan 执行求解器／宏。停止后不再开下一件，当前工艺需完成或手动结束。 |
| 简易制作 | 配方及角色须满足游戏简易制作条件；每批最多 99 次。不满足条件时停止，不自动回退到标准制作。停止会请求取消当前批次后续次数，再等实际结果和窗口释放。 |
| 跟随 Artisan 设置 | 兼容方式调用公开 `CraftItem`，沿用 Artisan 设置。尚未确认接收的私有预处理队列不能通过公开接口撤回，停止可能持续阻塞并需要人工处理。 |

可选“制作前从本角色雇员补齐缺少的材料与水晶”。按计划全部次数准备材料，需要制作角色已在附近雇员铃；缺料、空间不足或取出结果不明时停止，不暗中减少次数或重复提交未知请求。它不会自动切换制作职业。

## 开始前设置

1. **停用旧 RetainerCraftBridge／雇员收取后制作和 RetainerVendorSweep／多角色雇员直售插件。** 新插件独立安装和配置，不与旧两个插件同时接管；不需要替换原版 AR、Artisan 或 Lifestream DLL。
2. 加载 AutoRetainer 与 Lifestream；仅启用制作时必须加载 Artisan。先关闭 AR 多角色模式并等待现有任务结束。将 AR 多角色范围设为 **Retainers（仅雇员）**。
3. 关闭 AR 的旧 Artisan 整合、RetainerSense／OldRetainerSense、自动军票交付、夜间模式，以及启动游戏／加载插件时自动开启多角色（`MultiAutoStart`／`MultiOnPluginLoad`）。运行前取消 AR 私有的一次性 Synchronize 模式；该运行态没有公开 getter，工坊无法准确复刻。
4. 在 `/ays settings → 高级设置 → 专家设置 → 行为设置` 中，将有／无可用探险时的普通开铃操作都设为 **Disable_AutoRetainer（禁用 AutoRetainer）**。可以长期保持这两项设置：AR 自己的多角色自动开铃使用独立分支；工坊自行开铃取料／出售时则需要避免 AR 抢先收取。
5. 停止其他制作、换角、交易及背包自动化。刷新 AR 已知角色，核对首尾及制作角色、出售角色、出售规则与保留名单，再从界面的确认清单手动开始。

若没有 AR 范围选择器：`/ays settings → 高级设置 → 专家设置 → 显示多角色模式类型选择器`，再返回 AR 主窗口，在“多角色”旁选择 Retainers。

工坊通过公开接口切换 AR 运行开关，不自动修改上述共存选项。开头到期判定沿用该角色已勾选、执行中探险的 `MultiWaitForAll`（任一／全部）与 `AdvanceTimer` 提前窗口，不等待全账号到齐。

## 命令、延迟与停止

| 命令 | 用途 |
| --- | --- |
| `/workshop` | 打开配置、预览及运行界面 |
| `/workshop stop` | 停止后续收取、制作、出售与换角，等待已发请求收尾 |

轮换边界、取料、制作和直售的步骤延迟分别可调，动作最低间隔为 100 毫秒。轮换边界延迟只影响工坊自己的启动、换角和交接，不改变 AR 内部收取或派遣步骤速度。直售按整堆提交，没有数量窗口步骤。

停止不是撤销已经交给游戏的出售、制作、登出或登录。已发请求必须等响应并释放自身界面；未知结果仍显示阻塞，不能因窗口暂时消失就重新运行。先停止并等待空闲再卸载；卸载后不能依靠下一帧完成清理，兼容方式的 Artisan 私有请求尤其需要人工核对。停止及卸载不会自动恢复旧制作或 AR 轮换。

## 导入旧配置与保护名单

“导入旧配置”先读取并预览旧制作桥接 v2、直售 v1 配置，只有点击确认应用才写入新插件配置。旧文件保持不变，不解析或加载旧插件 CLR 类型。

可导入角色选择、配方／模式、制作和取料延迟、出售物品／品类／品质、直售角色顺序与延迟。**保留名单合并当前设置与旧配置，不删除已经设置的保护**；保护字段缺失、损坏或存在不合法内容时拒绝导入。

导入不带入旧 `Enabled`，不自动开始任务，也不覆盖新插件的制作启用选择、收尾角色、轮换延迟、周期规则和 M 上限。导入后仍需单独选择收尾角色并核对实际设置。

## 环境、安装与验证边界

目标环境为 Windows x64、.NET 10、国服 Soil／Dalamud API 15，固定 SDK `26-11-03-01`，游戏版本限定 **2026.10.06.0000.0000**。接口核对基准为 AutoRetainer 4.6.0.8、Lifestream 2.6.0.5、Artisan 4.0.5.21；其他版本需要重新核实，不能假定原生结构及接口时序兼容。

源码仓库：[Houraiji9/FFXIV-StandalonePlugins](https://github.com/Houraiji9/FFXIV-StandalonePlugins)。发布后通过相同自定义仓库地址安装，搜索“雇员工坊”或 `RetainerWorkshop`：

```text
https://raw.githubusercontent.com/Houraiji9/FFXIV-StandalonePlugins/main/pluginmaster.json
```

新插件独立保存配置、周期账本和中断记录；这些记录不构成可恢复的游戏队列，加载时不会续跑，也不随发布包上传个人角色资料。旧插件保留原配置和发行包，是否安装新插件由用户决定。

本地可执行以下构建和会话检查；完整检查入口及最终结果以仓库根说明和本轮交付记录为准：

```powershell
dotnet build plugins/RetainerWorkshop/RetainerWorkshop.csproj -c Release
dotnet run --project tests/RetainerWorkshop.Sessions.Tests/RetainerWorkshop.Sessions.Tests.csproj -c Release
```

当前源码借用既有制作、取料、直售引擎编译进独立程序集，不依赖旧两个插件 DLL。源码采用 AGPL-3.0，来源与许可见仓库 `THIRD-PARTY-NOTICES.md`。既有引擎的静态证据和测试不能替代新调度器的独立审查，更不能替代完整实机流程与用户验收。
