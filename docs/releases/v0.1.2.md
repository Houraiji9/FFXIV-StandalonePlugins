# BatchTrade 0.1.2 预发布

修复 0.1.1 正常放入物品时仍提示“待填交易格或此前已填物品格被修改”的问题。本次只更新 BatchTrade；RetainerCraftBridge 仍为 0.1.0.0。

旧版错误地要求交易缓存保留源背包格的 symbolic 链接。实际的游戏 getter 已解析该链接，缓存保存普通物品身份及本笔数量，因此正常物品也会被拒绝。新版从实际交易容器的原始格核对来源，再核对缓存物品和数量，不再混用这两种数据。

- 保留单笔合计 **1–999**、最多五格、HQ/NQ 隔离以及全部 **10 项可调延迟**。
- 区分待初始化、数量输入与缓存同步阶段；空格或尚未完成同步的状态不能授权确认交易。
- 正确处理数量为零但仍残留物品 ID 或链接字段的空格。
- 增加明确的失败原因与可复制诊断，包括步骤、格号、预期/实际物品及数量；不包含角色名、实体 ID 或内存地址。

在插件安装器刷新原仓库，更新“批量物品交易”后用 `/batchtrade` 打开。自定义仓库地址保持不变：

```text
https://raw.githubusercontent.com/Houraiji9/FFXIV-StandalonePlugins/main/pluginmaster.json
```

仍限定国服客户端 `2026.10.06.0000.0000`、Dalamud API 15。旧版分析中的错误已在仓库证据文档中明确更正。编译、离线检查和静态分析不代表新版已经完成真实游戏交易验收。
