# BatchTrade 0.1.5 预发布

批量物品交易新增 **按组数 / 按个数** 两种数量输入。刷新原自定义仓库，更新“批量物品交易”，通过 `/batchtrade` 打开设置。

- 按组数时，一组自动取所选物品本身的堆叠上限。10 组上限 999 的物品为 **9,990 个**；上限 99 为 **990 个**；上限 1 为 **10 个**。
- 输入框下实时显示“组数 × 每组个数 = 总个数”。更换物品立即重新换算，开始后锁定本次总量。
- 两种方式分别保存输入值，来回切换互不覆盖。旧配置默认按个数，原总量与延迟设置保留；非整组数量继续按个数填写。
- 每格交易上限只控制分装，不改变每组的个数。一笔最多五格；10 个完整的 999 堆、每格上限 999 时，按两笔各五格完成。
- 零、负数组数或换算后超出 1–10,000,000 个时阻止开始，不会自动缩减组数。库存不足仍会明确停止。
- 两种数量框均严格检查完整数字文本，小数和超大整数不能被截成另一笔有效数量。

自定义仓库地址不变：

```text
https://raw.githubusercontent.com/Houraiji9/FFXIV-StandalonePlugins/main/pluginmaster.json
```

本次只更新 BatchTrade 到 0.1.5.0，RetainerCraftBridge 保持 0.1.4.0。目标环境为国服客户端 `2026.10.06.0000.0000`、Dalamud API 15、.NET 10。原有十项操作延迟和交易结算规则继续沿用。

BatchTrade 218 项离线规则检查通过，包含新增 38 项数量换算与规划边界检查。发布前执行完整构建、其余三组回归、独立静态复核及安装包校验；这些不替代游戏内按组交易的验收，开发期间未执行真实交易。
