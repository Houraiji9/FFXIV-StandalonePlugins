# BatchTrade 0.1.1 预发布

本次仅更新**批量物品交易（BatchTrade）**。RetainerCraftBridge 保持 0.1.0.0，其下载地址和配置不变。

目标为国服 Dalamud API 15、游戏版本 `2026.10.06.0000.0000`。交易回调布局仅在这个已核对的游戏版本启用，未知版本拒绝执行。

- 单笔总数量上限可填写 **1–999**，支持按 1、99、999 等值拆分；多格物品的合计数量也受该上限限制。总量 3259、单笔 999 时，分为 999 + 999 + 999 + 262。
- 各个操作步骤提供独立延迟设置。等待前一步游戏状态后才执行下一步，保持最小动作间隔，避免同一帧连续发出多个操作。
- 修正数量及确认弹窗的回调归属判断。当前客户端的交易数量框和最终确认框由背包系统内嵌的回调接收者处理，旧版错误地要求它们属于 `AgentTrade`。新版使用针对已核对游戏版本的适配，并保留源物品格、交易目标、提示与数量范围验证。
- 支持数量窗口跨帧创建：创建时先记录本次操作的窗口，后续步骤再核对回调。数量范围按实际弹窗验证，不再要求弹窗最大值等于背包整堆数量。
- 修正交易栏物品引用和临时数量的识别：原物品堆大于 1 时，即使本笔只交易 1 个，也必须等待本次数量窗口提交，不能把游戏先放入的临时 1 个当作已经填好。
- 延迟等待与游戏响应超时分开计算；主动停止会撤销尚未发出的步骤。

更新时，在插件安装器刷新原仓库并更新“批量物品交易”，用 `/batchtrade` 打开新增设置。仓库地址不变：

```text
https://raw.githubusercontent.com/Houraiji9/FFXIV-StandalonePlugins/main/pluginmaster.json
```

0.1.0 已收到真实客户端反馈：插件能加载，但数量弹窗校验会中止交易。本版针对该路径修复，并完成离线验证；**仍需更新后核实真实交易结果，不能将编译、模拟测试或公开下载成功当作游戏验收。** 延迟有助于控制操作节奏，不构成“不会闪退”的保证。
